# banner WEB 用例

### TC-banner-WEB-001: Banner 列表展示与上下架徽标
**关联需求**: banner/web 端 Banner 管理页面#列表展示与状态徽标
**来源**: baseline-auth-manager-banner-log-file
**优先级**: P0
**前置条件**: Manager 账号可登录 http://100.100.117.79:5173/love-space/signin；系统中存在若干 Banner，其中至少一个关联城市已被删除（关联城市为空）
**测试步骤**:
1. 登录后台，进入 http://100.100.117.79:5173/love-space/banners
2. 查看筛选栏与列表表头
3. 逐行查看名称、位置标识、类型、关联城市、排序、上下架、更新时间、操作各列取值
**预期结果**: 筛选栏含「名称」「位置标识」「类型」「上下架」四项；列表列为名称、位置标识、类型、关联城市、排序、上下架徽标、更新时间、操作；上下架列以徽标形式显示上架/下架；未关联城市（城市已删）的行「关联城市」列显示 `-`
**状态**: ⚠️ 环境阻塞
**执行方式**: web-test-runner（@playwright/mcp）
**执行存证**:

### TC-banner-WEB-002: 上架乐观更新失败后回滚并提示
**关联需求**: banner/web 端 Banner 管理页面#上下架乐观更新失败回滚
**来源**: baseline-auth-manager-banner-log-file
**优先级**: P0
**前置条件**: Manager 已登录；列表中存在一个「下架」状态的 Banner，且其关联城市为**下架**状态（后端上架必然失败）
**测试步骤**:
1. 进入 http://100.100.117.79:5173/love-space/banners，定位到该 Banner 所在行
2. 点击该行的「上架」操作，立即观察徽标状态（乐观更新阶段）
3. 等待后端响应返回后，再次观察该行徽标与页面提示
**预期结果**: 点击后徽标**先本地翻转**为「上架」；收到 400 失败响应后徽标**回滚**为「下架」，并弹出错误提示（文案为后端中文业务错误，如「关联城市已下架，无法上架」）；刷新页面后该 Banner 仍为下架
**状态**: ⚠️ 环境阻塞
**执行方式**: web-test-runner（@playwright/mcp）
**执行存证**:
**最后更新**: 2026-08-21

### TC-banner-WEB-003: 删除 Banner 需二次确认
**关联需求**: banner/web 端 Banner 管理页面#删除需确认
**来源**: baseline-auth-manager-banner-log-file
**优先级**: P0
**前置条件**: Manager 已登录；列表中存在至少两个 Banner（一个用于取消、一个用于确认删除）
**测试步骤**:
1. 进入 http://100.100.117.79:5173/love-space/banners
2. 对 Banner A 点击「删除」，读取确认弹窗文案，点「取消」
3. 对 Banner B 点击「删除」，在确认弹窗中点「确认」
4. 观察列表刷新后的行数与内容
**预期结果**: 两次均弹出确认框，且弹窗文案中包含对应 Banner 的名称；点「取消」后 Banner A 仍在列表中；点「确认」后 Banner B 从列表中消失
**状态**: ⚠️ 环境阻塞
**执行方式**: web-test-runner（@playwright/mcp）
**执行存证**:
**最后更新**: 2026-08-21

3. 展开「关联城市」下拉，读取全部选项
**预期结果**: 表单含名称、位置标识、排序（非负整数输入）、类型、关联城市、图片（多图上传）字段；关联城市下拉选项中出现上架城市，**不出现**下架城市

**执行方式**: web-test-runner（@playwright/mcp）
