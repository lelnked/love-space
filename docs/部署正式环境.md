# 部署正式环境（构建 → 上传 → 部署脚本）

> 本文档只覆盖应用部署流程，不包含 PostgreSQL 初始化（PostgreSQL 部署见 `部署服务器初始化.md` 第四节）。
> 目标服务器：`root@119.29.108.66`。

---

## 1. 本地构建

```bash
# 前端
cd love-space-web
npm install            # 首次或依赖变更时
npm run build          # 产物在 dist/

# admin 后端
cd ../love-space-admin
./mvnw clean package -DskipTests   # 产物在 target/love-space-admin-*.jar

# app 后端
cd ../love-space-app
./mvnw clean package -DskipTests   # 产物在 target/love-space-app-*.jar
```

---

## 2. 上传到服务器

在仓库根目录执行：

```bash
# 首次部署需要先建目录（已存在可跳过）
ssh root@119.29.108.66 "mkdir -p /app/loveSpace/{admin,app,web,deploy}"

# 上传 admin
scp love-space-admin/target/love-space-admin-*.jar  root@119.29.108.66:/app/loveSpace/admin/
scp love-space-admin/Dockerfile                     root@119.29.108.66:/app/loveSpace/admin/

# 上传 app
scp love-space-app/target/love-space-app-*.jar      root@119.29.108.66:/app/loveSpace/app/
scp love-space-app/Dockerfile                       root@119.29.108.66:/app/loveSpace/app/

# 上传前端静态文件
scp -r love-space-web/dist/*                        root@119.29.108.66:/app/loveSpace/web/

# 上传部署脚本
scp deploy/*.sh                                     root@119.29.108.66:/app/loveSpace/deploy/
# .env.prod 含敏感值且不在 git 里，只在首次或配置变更时单独传：
# scp deploy/.env.prod                               root@119.29.108.66:/app/loveSpace/deploy/
```

---

## 3. 配置 OSS 环境变量（仅首次需要）

```bash
ssh root@119.29.108.66
cat >> ~/.bashrc << 'EOF'
export ALIYUN_OSS_REGION=cn-hangzhou
export ALIYUN_OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
export ALIYUN_OSS_BUCKET=love-space-test-0524
export ALIYUN_OSS_ACCESS_KEY_ID=<your-key-id>
export ALIYUN_OSS_ACCESS_KEY_SECRET=<your-key-secret>
export ALIYUN_STS_ROLE_ARN=acs:ram::1220279335098944:role/oss-sts
EOF
source ~/.bashrc
```

---

## 4. 执行部署脚本（服务器上执行）

```bash
ssh root@119.29.108.66
cd /app/loveSpace/deploy
DEPLOY_ENV=prod bash deploy-apps.sh 1.0.0    # 版本号自定义，会作为 docker 镜像 tag
# DEPLOY_ENV 决定读哪份 deploy/.env.<环境>；不传会直接报错，防止把测试配置发到生产
```

`deploy-apps.sh` 会按顺序构建并启动 admin（先启动，负责跑 Liquibase 建表）和 app 两个容器。

---

## 5. nginx（仅前端目录或代理变更时）

前端静态文件直接被 nginx 读取，**无需重启**。如修改了 `tripleyourlife.com.conf`：

```bash
docker exec nginx-tripleyourlife nginx -t          # 验证语法
docker exec nginx-tripleyourlife nginx -s reload   # 热重载
```

---

## 日常更新简版

- **只更后端**：本地 `./mvnw clean package -DskipTests` → `scp` jar → 服务器 `DEPLOY_ENV=prod bash deploy-apps.sh 1.0.x`（版本号递增）
- **只更前端**：本地 `npm run build` → `scp -r dist/* …:/app/loveSpace/web/`，无需重启
- **前后端同时**：依次执行上面两步
