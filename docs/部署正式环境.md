## 1. 本地构建

```bash
# 前端
cd love-space-web
npm install                                    # 首次或依赖变更时（需 NODE_ENV=development）
cp .env.production.example .env.production     # 首次；.env.production 不入 git，构建机需自备
npm run build                                  # mode 默认 production → 读 .env.production；产物在 dist/

# 核对产物里编译进去的后端地址（应为 https://www.tripleyourlife.com/love-space/admin）
grep -o 'https\?://[^"]*love-space/admin' dist/assets/*.js | head -1

# admin 后端
cd ../love-space-admin
./mvnw clean package -DskipTests   # 产物在 target/love-space-admin-*.jar

# app 后端
cd ../love-space-app
./mvnw clean package -DskipTests   # 产物在 target/love-space-app-*.jar
```

---

## 2. 上传到服务器

在仓库根目录执行：

```bash
# 首次部署需要先建目录（已存在可跳过）
ssh root@119.29.108.66 "mkdir -p /app/loveSpace/{admin,app,web,deploy}"

# 上传 admin
scp love-space-admin/target/love-space-admin-*.jar  root@119.29.108.66:/app/loveSpace/admin/
scp love-space-admin/Dockerfile                     root@119.29.108.66:/app/loveSpace/admin/

# 上传 app
scp love-space-app/target/love-space-app-*.jar      root@119.29.108.66:/app/loveSpace/app/
scp love-space-app/Dockerfile                       root@119.29.108.66:/app/loveSpace/app/

# 上传前端静态文件
scp -r love-space-web/dist/*                        root@119.29.108.66:/app/loveSpace/web/

# 上传部署脚本
scp deploy/*.sh                                     root@119.29.108.66:/app/loveSpace/deploy/
# .env.prod 含敏感值且不在 git 里，只在首次或配置变更时单独传：
# scp deploy/.env.prod                               root@119.29.108.66:/app/loveSpace/deploy/
```

## 3. 配置环境变量（仅首次 / 配置变更时需要）

**所有环境相关配置（DB 地址、JWT secret、API key、阿里云 OSS）都写在服务器的
`/app/loveSpace/deploy/.env.prod` 里，不写进 `~/.bashrc`、不写进脚本、不入 git。**
部署脚本靠 `DEPLOY_ENV=prod` 找到这份文件（模板见仓库 `deploy/.env.example`）。

本地填好后单独上传（含密钥，日常发版不需要重传）：

```bash
cp deploy/.env.example deploy/.env.prod    # 首次；.env.* 已被 .gitignore 忽略
vi deploy/.env.prod                        # 填 DB_HOST / ADMIN_JWT_SECRET / APP_SECURITY_API_KEYS / OSS 各项
scp deploy/.env.prod root@119.29.108.66:/app/loveSpace/deploy/
```

生产需要填的 OSS 项（值以团队密钥管理为准，不写进本文档）：

```bash
ALIYUN_OSS_REGION="${ALIYUN_OSS_REGION:-cn-hangzhou}"
ALIYUN_OSS_ENDPOINT="${ALIYUN_OSS_ENDPOINT:-oss-cn-hangzhou.aliyuncs.com}"
ALIYUN_OSS_BUCKET="${ALIYUN_OSS_BUCKET:-<生产 bucket>}"
ALIYUN_OSS_ACCESS_KEY_ID="${ALIYUN_OSS_ACCESS_KEY_ID:-<your-key-id>}"
ALIYUN_OSS_ACCESS_KEY_SECRET="${ALIYUN_OSS_ACCESS_KEY_SECRET:-<your-key-secret>}"
ALIYUN_STS_ROLE_ARN="${ALIYUN_STS_ROLE_ARN:-acs:ram::1220279335098944:role/oss-sts}"
```

> 写成 `X="${X:-值}"` 是为了让 shell 里已存在的同名变量优先，方便临时覆盖单项。

## 4. 执行部署脚本（服务器上执行）

```bash
ssh root@119.29.108.66
cd /app/loveSpace/deploy
DEPLOY_ENV=prod bash deploy-apps.sh 1.0.0    # 版本号自定义，会作为 docker 镜像 tag
# DEPLOY_ENV 决定读哪份 deploy/.env.<环境>；不传会直接报错，防止把测试配置发到生产
```

`deploy-apps.sh` 会按顺序构建并启动 admin（先启动，负责跑 Liquibase 建表）和 app 两个容器。

---

## 5. nginx（仅前端目录或代理变更时）

前端静态文件直接被 nginx 读取，**无需重启**。如修改了 `tripleyourlife.com.conf`：

```bash
docker exec nginx-tripleyourlife nginx -t          # 验证语法
docker exec nginx-tripleyourlife nginx -s reload   # 热重载
```

## 日常更新简版

- **只更后端**：本地 `./mvnw clean package -DskipTests` → `scp` jar → 服务器 `DEPLOY_ENV=prod bash deploy-apps.sh 1.0.x`（版本号递增）
- **只更前端**：本地 `npm run build` → `scp -r dist/* …:/app/loveSpace/web/`，无需重启
- **前后端同时**：依次执行上面两步
