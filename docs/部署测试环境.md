### 2.3 环境变量（服务器 `deploy/.env.test`，只需一次）

**所有环境相关配置（DB 地址、JWT secret、API key、阿里云 OSS）都写在服务器的
`/app/loveSpace/deploy/.env.test` 里，不写进 `~/.bashrc`、不写进脚本、不入 git。**
脚本靠 `DEPLOY_ENV=test` 找到这份文件（模板见仓库 `deploy/.env.example`）。

本地按模板填好后传上去（含密钥，只在首次或配置变更时传）：

```bash
cp deploy/.env.example deploy/.env.test    # 首次；.env.* 已被 .gitignore 忽略
vi deploy/.env.test                        # 填 DB_HOST / ADMIN_JWT_SECRET / APP_SECURITY_API_KEYS / OSS 各项
scp deploy/.env.test lo_test:/app/loveSpace/deploy/
```

测试环境需要填的 OSS 项（值以团队密钥管理为准，不写进本文档）：

```bash
ALIYUN_OSS_REGION="${ALIYUN_OSS_REGION:-cn-hangzhou}"
ALIYUN_OSS_ENDPOINT="${ALIYUN_OSS_ENDPOINT:-oss-cn-hangzhou.aliyuncs.com}"
ALIYUN_OSS_BUCKET="${ALIYUN_OSS_BUCKET:-love-space-test-0524}"
ALIYUN_OSS_ACCESS_KEY_ID="${ALIYUN_OSS_ACCESS_KEY_ID:-<your-key-id>}"
ALIYUN_OSS_ACCESS_KEY_SECRET="${ALIYUN_OSS_ACCESS_KEY_SECRET:-<your-key-secret>}"
ALIYUN_STS_ROLE_ARN="${ALIYUN_STS_ROLE_ARN:-acs:ram::1220279335098944:role/oss-sts}"
```

> 写成 `X="${X:-值}"` 是为了让 shell 里已存在的同名变量优先，方便临时覆盖单项，例如
> `ALIYUN_OSS_BUCKET=other DEPLOY_ENV=test bash deploy-apps.sh <版本>`。

## 三、部署步骤

### 3.1 本地构建

在仓库根目录 `/home/linked/personal/love-space` 执行：

```bash
# 前端
cd love-space-web
npm install            # 依赖变更时执行
npm run build          # 产物：dist/

# admin 后端
cd ../love-space-admin
mvn clean package -DskipTests   # 产物：target/love-space-admin-*.jar

# app 后端
cd ../love-space-app
mvn clean package -DskipTests   # 产物：target/love-space-app-*.jar
```

### 3.2 上传到服务器

```bash
# 创建目录
ssh lo_test 'mkdir -p /app/loveSpace/{admin,app,web,deploy}'

# 上传 admin
scp love-space-admin/target/love-space-admin-*.jar  lo_test:/app/loveSpace/admin/
scp love-space-admin/Dockerfile                     lo_test:/app/loveSpace/admin/

# 上传 app
scp love-space-app/target/love-space-app-*.jar      lo_test:/app/loveSpace/app/
scp love-space-app/Dockerfile                       lo_test:/app/loveSpace/app/

# 上传前端静态文件
scp -r love-space-web/dist/*                        lo_test:/app/loveSpace/web/

# 上传部署脚本
scp deploy/*.sh                                     lo_test:/app/loveSpace/deploy/
# .env.test 含敏感值且不在 git 里，只在首次或配置变更时单独传：
# scp deploy/.env.test                               lo_test:/app/loveSpace/deploy/
```

### 3.3 执行部署脚本

```bash
ssh lo_test 'cd /app/loveSpace/deploy && DEPLOY_ENV=test bash deploy-apps.sh <版本>'
# DEPLOY_ENV=test → 读 deploy/.env.test（DB 地址、JWT、API key、OSS 等环境差异都在那里）
```

示例：

```bash
ssh lo_test 'DEPLOY_ENV=test bash /app/loveSpace/deploy/deploy-apps.sh 20260824-1225'
```

> 版本号自定义，会作为 Docker 镜像 tag，例如 `love-space-admin:20260824-1225`。

## 六、注意事项

- **admin 必须先于 app 启动**：admin 负责执行 Liquibase 建表，app 不跑迁移。`deploy-apps.sh` 已保证顺序。
- **数据库地址**：服务器内网 IP 为 `172.26.150.96`，PostgreSQL 映射端口 `8954`，容器通过 host 网络访问。
- **前端 base 路径**：Vite 构建产物和 nginx 配置均使用 `/love-space/` 前缀。
- **版本号递增**：每次部署使用新的版本号，避免镜像 tag 冲突。
- **环境变量**：唯一来源是服务器 `/app/loveSpace/deploy/.env.test`（见 2.3）。脚本不传 `DEPLOY_ENV` 会直接报错，不会用默认值蒙混过去。
- **数据库地址等环境差异**：都在 `.env.test` 里，本文正文出现的具体值仅供参考，以该文件为准。
