# 需求1. 推荐清单城市-商户联动与下架联动（Recommend List City-Merchant Cascade & Off-shelf Cascade）

本需求让 web 后台的推荐清单创建/编辑具备“先选城市，再选该城市商户”的级联选择，并把“商户后期下架”反映到推荐清单的可消费状态上，避免 app 端展示已失效商户或已失效推荐。

## 范围与边界（保证需求独立）

| 本需求不实现 | 归属 |
|---|---|
| 城市/地图的创建、下架、恢复等基础字段 | city living spec |
| 商户创建/编辑的基础字段与图片 | merchant living spec |
| 推荐清单列表页通用 DataTable、删除确认等基础交互 | recommend-list living spec 既有行为 |
| app 端清单详情与列表的只读展示口径 | recommend-list living spec 既有行为 |
| 后台权限、登录与会话 | auth living spec |

> 因此本需求接口请求体仅含本需求新增/变更字段；其余字段沿用既有口径。

## 数据模型

### 推荐清单（RecommendList）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 标识 | PK | 清单唯一标识 |
| title | 字符串 | 必填 | 清单标题 |
| description | 文本 | 可空 | 清单介绍 |
| cityId | 标识 | 必填 | 所属城市，创建后可修改 |
| sortOrder | 整数 | 必填 | 清单排序，同城市内升序 |
| status | 枚举 | 必填 | 新增字段：`ONLINE` / `OFFLINE`。默认 `ONLINE`。用于承载商户下架级联结果。 |
| createdAt | 时间戳 | 系统生成 | 创建时间 |
| updatedAt | 时间戳 | 系统生成 | 更新时间 |

**唯一性规则**：本需求不新增唯一约束；若项目后续要求同一城市下 title 唯一，请单独开 change。
**权限点**：`recommend-list:read`、`recommend-list:create`、`recommend-list:update`、`recommend-list:delete`；写操作记审计。

### 推荐清单-商户关联（RecommendListMerchant）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| recommendListId | 标识 | PK/FK | 关联清单 |
| merchantId | 标识 | PK/FK | 关联商户 |
| sortOrder | 整数 | 必填 | 关联排序，同清单内升序 |

**唯一性规则**：同一清单内同一商户仅可存在一条关联。
**权限点**：同 `recommend-list`。

### 商户（Merchant）
复用既有 merchant 模型，本需求只消费其下架状态（`status` 或等价字段）。若项目当前用 `enabled/disabled`、`online/offline`、`active/inactive` 等枚举，后端按既有口径映射即可。

## 1.1 推荐清单查询与城市筛选

一句话：在 web 后台可按城市筛选推荐清单，列表展示状态与商户数。

**实施方案**：
1. 查询清单列表时支持按 `cityId` 过滤；列表增加 `status` 字段展示。
2. 统计每个清单当前有效关联商户数；若当前商户数为 0，不影响列表展示，由产品后续决定是否提示。
3. 请求/响应沿用既有清单列表接口，若接口字段不足则在此 change 中扩展。

**界面落点**：推荐清单列表页的城市筛选下拉；列表的状态列。

## 1.2 城市-商户级联选择

一句话：创建/编辑推荐清单时，先选所属城市，再只选该城市下未下架的商户，且同一清单不可重复添加同一商户。

**实施方案**：
1. 表单新增/沿用 `cityId`、`status`；编辑时允许修改城市。
2. 城市变更或初始化时，触发商户下拉选项刷新；选项来源为“该城市且未下架的商户”列表。
3. 添加商户时做业务校验：
   - 同一清单内已存在该商户 → 400 中文提示；
   - 商户不属于所选城市 → 400 中文提示；
   - 商户已下架 → 前端下拉已过滤，后端仍兜底校验并拒绝。
4. 保存时若表单包含商户关联，一并持久化；排序号沿用表单内维护逻辑或默认升序。
5. 若编辑中把城市改到另一个城市，已有商户若不属于新城市，接口返回 400 并提示需清理；或由前端清空已选并提示用户重新选择。

**界面落点**：新建/编辑表单的城市下拉、商户下拉、加入按钮、已选商户列表与移除按钮。

## 1.3 商户下架级联下架推荐清单

一句话：若清单关联商户被后期下架，该推荐清单自动下架；恢复商户后不自动恢复清单，需人工复核再上架。

**实施方案**：
1. 推荐清单新增 `status` 枚举：`ONLINE`、`OFFLINE`。
2. 后台提供“商户下架”接口/动作；执行时查询所有包含该商户且状态为 `ONLINE` 的推荐清单，批量置为 `OFFLINE`。
3. 级联记录变更原因，便于审计与提示；不删除关联，保留历史商户组成。
4. app 端查询推荐清单列表/详情时，仅返回 `status = ONLINE` 的清单及其商户；`OFFLINE` 清单对 app 不可见。
5. 人工将清单重新置为 `ONLINE` 前，后端校验该清单当前是否还存在已下架商户：存在则拒绝恢复并返回中文提示；不存在则允许恢复。

**界面落点**：web 端推荐清单列表的状态列；编辑表单的状态单选项；保存前若存在下架商户提示。

| 编号 | 方法 | 路径 | 权限 | 请求体 | 响应 |
|---|---|---|---|---|---|
| 1.1 | GET | `/api/admin/recommend-lists` | `recommend-list:read` | `cityId?`、`page`、`size` | 清单列表，含 `status` 与商户计数 |
